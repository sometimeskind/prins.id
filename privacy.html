Privacy

Last updated 15 September 2026

This page covers this website and calendar-sync, a personal application that copies my own Google Calendars onto a server I operate. Both are run by one person for their own use. Neither is a product, neither has other users, and neither is offered as a service to anyone else.

This website

It serves a single emoji. It sets no cookies, runs no analytics, and embeds nothing from third parties. The web server keeps ordinary access logs, which include the requesting IP address, in the normal course of operating it.

What calendar-sync accesses

calendar-sync signs in to Google as me, using OAuth 2.0 with the https://www.googleapis.com/auth/calendar scope, and reads calendar events over Google's CalDAV API. It only reads calendars I have explicitly listed in its configuration and explicitly exposed on Google's CalDAV settings page.

Google requires that scope for CalDAV access and it permits writing as well as reading. calendar-sync is configured read-only and never writes to Google: Google remains the authoritative copy, and the mirror only follows it.

How the data is used and stored

Calendar events are copied to a calendar server on hardware I own and operate, so that I can read my own calendars from my own devices. The data is used for nothing else. It is not profiled, not analysed, and not used for advertising.

Who it is shared with

Nobody. The data is not sold, not shared with third parties, not sent to any analytics or advertising service, and not used to train anything. It goes from Google to my server and stops there.

Retention, and withdrawing access

The mirrored copy is kept for as long as I keep running the application, and is deleted when I stop. Access can be withdrawn at any time from Google Account permissions, which immediately revokes the application's token; nothing further is read after that.
